# 既有项目规范采集

## 调查范围

调查当前任务涉及的领域及相关 README、AGENTS、需求、源码、测试和必要配置。规范采集以事实为依据，只处理当前任务需要的内容。

## 采集内容

| 规范内容 | 采集目标 | 事实来源 |
| --- | --- | --- |
| 项目背景及约束 | 项目用途、系统目标、主要能力、技术环境和长期约束 | README、AGENTS、运行配置、依赖及已确认目标 |
| 领域边界 | 业务能力、核心概念、规则边界和领域关系 | 业务说明、接口、数据关系、源码及测试 |
| 当前需求 | 功能用途、处理规则、输入输出、完整数据过程和边界结果 | 现有需求、测试、源码及已确认目标 |
| 架构与设计 | 系统关系、领域模型、数据模型和公共接口 | 源码、配置、接口定义、部署说明及运行环境 |
| 术语 | 实际使用的概念、定义和所属领域 | 现有文档、源码、接口和数据模型 |
| 本次差异 | 当前有效规范、已接受 Change 与实际实现之间的差异 | 当前规范、Change、源码及测试 |

实际行为由源码和运行证据确认；预期需求由已有规范、验收测试和已确认的业务语义确定。材料存在冲突时先调查，无法确定的业务语义需要澄清。

## 填写原则

- 按 [domain-modeling.md](domain-modeling.md) 确定内容归属，按 [requirements-entry-format.md](requirements-entry-format.md) 描述需求规则和完整数据示例。
- 初始化文档表达已有系统当前状态，内容必须具有事实依据；尚未确定的内容保留模板结构和空分节。
- 规范采集包含当前任务相关的需求缺口，无关缺口只记录影响，不扩大本次范围。
- 结构、模板和索引规则见 [spec-structure.md](spec-structure.md)，操作命令见 [usage.md](usage.md)。

既有项目的批量迁移、历史重写和行为变化按明确授权范围执行。
