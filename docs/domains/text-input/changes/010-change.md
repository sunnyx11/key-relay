# 应用更新检查与确认安装

关联规范：[领域需求](../requirements.md)、[领域设计](../design.md)、[项目架构](../../../project/architecture.md)、[项目上下文](../../../project/context.md)、[发布说明](../../../release.md)、INPUT-REQ-006、INPUT-REQ-007、INPUT-REQ-008

## 变更原因

应用自动检查正式版本，安装版经确认后下载并安装更新，独立 EXE 提供人工下载入口。

## 变更前

- 关于页显示版本、支持链接和许可证。
- 升级由使用者下载安装包或替换独立 EXE。
- 发布附件为安装包、独立 EXE 和 SHA-256 文件。
- 退出结束输入任务并清理原生资源，文本仅驻留内存。

## 变更后

- 更新功能从 0.2.1 提供。0.1.0 需人工安装一次带更新功能的版本。
- 默认自动检查，启动完成 10 秒后检查，持续运行每 24 小时检查；关于页支持手动检查及关闭自动检查。偏好独立保存。
- 正式版本清单来自 GitHub 最新公开正式 Release，保留 HTTPS 与安装包签名验证；相同或更低版本保持当前版本。
- 检查和下载各保持单个操作。自动检查仅获取清单，使用者确认后才下载。
- 安装版提供下载、进度、安装及重启操作。独立 EXE 只显示版本、说明和下载入口，依据当前用户安装记录及可执行文件位置判断运行方式。
- 安装前明确提示编辑文本将在重启后清除；确认状态只保留在当前界面操作中。有效设置在更新后保留。
- 检查与下载允许输入任务继续。安装准备必须由原生任务线程确认空闲并阻止按钮和全局快捷键启动，释放监听及快捷键后才执行安装。
- 若下载完成时任务活动，保留已验证更新并等待新的安装确认；取消确认保留文本及当前任务。
- 下载结果仅保留于当前进程。断网、超时、签名错误显示明确状态，允许重试；签名错误阻止安装。
- 安装启动失败恢复原生资源和任务启动能力。安装程序接管后由其显示安装结果，成功后启动新版。
- 更新网络请求及诊断省略编辑文本。前端通过受限命令操作原生更新模块，更新地址和公钥由构建配置决定。
- 发布附件增加安装包 .sig 与 latest.json。SHA256SUMS.txt 校验另外四个附件。清单含版本、说明、日期、Windows x64 安装包固定版本地址及完整签名。
- 私钥由构建环境提供并在仓库外保存；公开版本保持完整附件，草稿经人工验收后公开。独立 EXE 自动替换、差量更新、断点续传和自动回滚属于范围外功能。

示例：安装版 0.2.1 检查发现 0.3.0 → 展示版本说明 → 确认下载 → 下载并验证签名 → 提示重启清除文本 → 确认且原生任务空闲 → 安装重启 → 0.3.0 显示原有效设置、空编辑框和空闲状态。
