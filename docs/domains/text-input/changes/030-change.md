# 配置最大历史条数

关联规范：INPUT-REQ-006、INPUT-REQ-007、[领域概览](../overview.md)、[领域设计](../design.md)、[项目架构](../../../project/architecture.md)、[项目原则](../../../project/principles.md)、[项目术语](../../../project/glossary.md)、[使用说明](../../../../README.md)、[Windows 人工验收](../../../../tests/manual/windows.md)

## 变更原因

设置页提供最大历史条数配置，满足不同历史保存数量的需要。

## 变更前

- 历史固定最多保存 100 条，置顶计入上限。
- 新增记录时淘汰最旧未置顶记录，全部置顶时跳过新增并提示。
- 文本保存区域仅提供草稿与历史保存开关。

## 变更后

- “文本保存”提供“最大历史条数”整数控件及“保存上限”按钮，默认 100，范围 1～10,000。
- 上限以 `maxHistoryEntries` 保存在 `text.json`，文本状态包含同名字段。现有文件缺少字段时采用 100。
- `change_text_state` 接收 `{"action":{"kind":"historyLimit","maxHistoryEntries":200}}`，返回包含新上限的完整文本状态。
- 点击“保存上限”一次提交并立即按新上限限制历史，置顶计入上限。新增记录和全置顶容量提示均使用配置值。
- 调低上限导致现有记录超限时，保存时即淘汰最旧未置顶记录。同时间先淘汰编号最小的记录，保留其余归档顺序、草稿及下一编号。
- 上限小于当前置顶数量时显示字段错误，设置和历史保留原值。无效整数及超出范围的值同样保持原值。
- 任务、安装、初始化、存储操作和中止释放保护期间禁用编辑与保存，遵循现有文本管理互斥规则。
- 关闭历史保存仍可配置上限；保存开关继续按既有规则保留已有数据。
- 历史清空和已保存草稿清除遵循各自的确认规则。

| 输入与操作 | 处理 | 输出 |
| --- | --- | --- |
| 默认上限 100，保存 200 后新增到 101 条 | 按 200 校验并归档 | 101 条均保留，重启读取上限 200 |
| 按归档顺序为 C(id=3,time=30)、B(id=2,time=20)、A(id=1,time=10,置顶)，保存上限 2 | 点击“保存上限”一次提交并淘汰 B | 保留 C、A，草稿及下一编号保留 |
| 2 条置顶，输入上限 1 | 显示至少保留 2 条的错误 | 保留原上限与全部记录 |
| 上限 2 且 2 条全部置顶，发送新原文 | 跳过新增历史并显示容量提示 | 输入继续，历史与下一编号保留 |
| 旧文本文件缺少 `maxHistoryEntries` | 按默认值读取 | 上限 100，草稿及历史保留 |
