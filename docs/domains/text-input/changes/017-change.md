# 输入框最小显示高度

关联规范：[领域设计](../design.md#界面视觉基准)、[项目原则](../../../project/principles.md#测试要求)

## 变更原因

输入框采用截图所示的 216px 最小显示高度，底部操作区随输入框缩短，三个页面保持等高。

## 变更前

- 编辑框基础高度为 184px，CSS 最小高度为 130px；共享面板最小高度为 258px，含 12px 上内边距，600px 窗口中的实际最小显示高度为 246px。
- 设置页仅占用内容区，输入操作区的空间在设置页保留。
- 前端尺寸计算和原生窗口的最小高度为 360px。

## 变更后

- 编辑框基础高度和最小高度均为 216px，支持向下拖动增高，再次缩小时遵守此下限。
- 输入面板最小高度为 228px，含 12px 上内边距。默认 600px 宽度下，输入框显示高度为 216px，原生窗口高度为 354px。
- 设置页跨越内容区和输入操作区，沿用现有控件尺寸和间距。隐藏的输入操作退出显示和焦点顺序。
- 前端尺寸计算和原生窗口最小高度统一为 354px，底部操作区紧邻输入框。
- 窄窗口、设置错误提示和文字换行可以增加共享高度，输入框填满可用内容区。输入、设置、关于及许可证在相同状态下保持等高。
- 关于页和许可证在可用区域内滚动，内容保持可访问。
- 原型与桌面应用使用相同的输入框和共享布局规则。

### 实现与验证

- 原型、桌面样式、前端尺寸计算和 Tauri 窗口下限已同步。领域设计、项目测试原则和 Windows 验收项采用相同尺寸。
- `npm test` 通过 22 项组件测试，`npm run test:e2e` 通过 18 项浏览器测试，`node prototypes/tests/run.mjs` 通过 25 项原型检查及更新交互检查。
- `npm run lint` 和 `npm run tauri -- build --no-bundle` 通过；桌面构建包含 TypeScript 检查和 Vite 构建。
- `npm run test:desktop` 通过 2 项 WebView2 桌面测试，覆盖首次打开、重新打开、编辑历史、增高缩小和最大化还原。
- 额外 WebView2 检查确认 Windows 100% 系统缩放下，600px 宽度对应 216px 编辑框和 354px 窗口；390px、320px 宽度下三个页签及许可证等高，设置说明完整。实际鼠标拖动可将编辑框增高至 300px 以上并缩回 216px。
- 编辑操作、任务保护和关于页保持现有实现，已随浏览器及桌面测试回归。Rust 任务引擎和发送协议保持现有实现，本次仅涉及界面尺寸与窗口约束；未新增抽象或依赖。
- 浏览器 100%／150% 缩放已验证。Windows 150% 系统缩放与跨显示器仍需人工验收。
