# 默认分支缓存与并行发布

关联规范：[发布说明](../../../release.md)、[项目架构](../../../project/architecture.md)

## 变更原因

发布检查与安装包构建并行执行，并复用默认分支的 Rust 依赖编译缓存，缩短版本标签的构建等待时间。

## 变更前

- 标签发布在单个 Windows 任务中依次执行前端检查、Rust 检查、规范检查、浏览器测试和安装包构建。
- npm 下载使用缓存，Rust 依赖和编译产物每次重新准备。
- 仓库没有默认分支 CI，标签之间无法互相读取 GitHub Actions 缓存。
- 浏览器测试安装完整 Chromium 和 Chromium Headless Shell。

## 变更后

- `main` 推送触发 Windows CI，支持手动执行。前端检查、Rust 检查和 Release 编译分别执行。
- 前端检查包含代码检查、组件测试、发布脚本测试、规范索引一致性检查及浏览器测试。浏览器只安装 Chromium Headless Shell。
- Rust 检查包含格式检查、Clippy 和常规 Rust 测试。Release 编译使用 Tauri `--no-bundle`，生成前端资源及 Release 编译产物，省去安装包生成和签名。
- CI 与发布任务统一使用 Windows Server 2022 x64、Node.js 24、Rust 1.91.1 和锁文件中的依赖。
- Rust 检查与 Release 编译使用独立缓存键。缓存包含 Cargo 依赖和 `src-tauri/target` 中的依赖编译产物，由默认分支成功任务保存，标签任务只恢复。
- 缓存键区分环境和编译用途，包含工具链、编译环境和依赖配置，支持锁文件变化时恢复旧依赖。缓存命中后仍执行检查和构建。
- 有效标签触发并行前端检查、Rust 检查和安装包构建。构建保留版本校验、签名要求、附件准备和锁文件一致性检查。
- Release 草稿等待三个任务全部成功。任一检查或构建失败时，草稿任务跳过。同标签发布保持串行，草稿权限与只读任务分开。
- npm 缓存由默认分支前端检查和 Release 编译任务准备，标签任务可读取默认分支缓存。
- 缓存缺失时执行完整检查和编译；实际耗时与跨版本缓存命中由 GitHub 托管环境验证。

示例：`main` CI 成功保存 Rust 检查和 Release 依赖缓存，随后推送有效标签 `v0.2.0`。三个标签任务并行读取可用缓存并执行检查或构建，全部成功后创建 Release 草稿。Rust 检查失败时，即使安装包构建成功，草稿任务仍跳过。
