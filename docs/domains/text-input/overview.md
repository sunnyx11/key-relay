# Domain 概览

## 领域目标

`text-input` 负责准备文本并向 Windows 目标程序模拟输入的业务规则，目标是减少无法粘贴场景中的手工输入。

## 职责边界

领域范围包含文本准备、草稿保存与启动恢复、历史输入记录的全文查看与恢复、任务启动、输入发送、人工中止和任务状态。首版功能与验收示例见[领域需求](requirements.md)。

目标程序拥有输入控件、键盘焦点及文本处理行为。工具发送事件与目标程序实际接收文本属于不同结果。

## 核心概念

待输入文本、已保存草稿、历史输入记录、目标输入位置、输入任务、目标激活、中止及完成的定义见[项目术语表](../../project/glossary.md)。

## 主要业务过程

业务过程如下，参数与边界条件以需求条目为准。

1. 启动入口检查单实例，重复启动唤起已有窗口。首个实例从用户数据目录读取设置，按保存选项恢复草稿；在工具中编辑文本，或查看历史全文后通过独立按钮恢复完整原文，见 INPUT-REQ-001、INPUT-REQ-006、INPUT-REQ-007。
2. 点击外部输入位置后，返回工具点击“开始输入”。按实时系统状态等待修饰键和鼠标按钮释放，激活并回点记录目标，见 INPUT-REQ-002、INPUT-REQ-003。
3. 向当前键盘焦点顺序发送文本，实际开始提交时归档冻结原文；鼠标移动和普通键盘操作继续，Esc 或鼠标按下中止，见 INPUT-REQ-004、INPUT-REQ-007。
4. 展示发送进度及完成、中止或错误结果，见 INPUT-REQ-005、INPUT-REQ-006。
5. 按保存选项及可配置的条数上限管理本机草稿和历史。关闭窗口隐藏到通知区域，托盘提供打开窗口、重置位置及退出应用；退出等待保存并释放输入监听资源，见 INPUT-REQ-007。

HTML 原型提供页内演示，Tauri 桌面应用负责实际 Windows 输入。具体结构见[领域设计](design.md)，真实 RDP 接收按[人工验收说明](../../../tests/manual/rdp.md)验证。
