# Domain 概览

## 领域目标

`text-input` 负责准备文本并向 Windows 目标程序模拟输入的业务规则，目标是减少无法粘贴场景中的手工输入。

## 职责边界

领域范围包含文本准备、任务启动、输入发送、人工中止和任务状态。首版功能与验收示例见[领域需求](requirements.md)。

目标程序拥有输入控件、键盘焦点及文本处理行为。工具发送事件与目标程序实际接收文本属于不同结果。

## 核心概念

待输入文本、目标输入位置、输入任务、倒计时、中止及完成的定义见[项目术语表](../../project/glossary.md)。

## 主要业务过程

业务过程如下，参数与边界条件以需求条目为准。

1. 在工具中准备文本，见 INPUT-REQ-001。
2. 选择目标后按全局快捷键，等待组合键全部释放；或点击“开始输入”，在倒计时期间选择目标，见 INPUT-REQ-002、INPUT-REQ-003。
3. 向当前键盘焦点顺序发送文本；鼠标移动继续，鼠标按下或实际键盘按键中止，见 INPUT-REQ-004。
4. 展示发送进度及完成、中止或错误结果，见 INPUT-REQ-005、INPUT-REQ-006。
5. 按本地数据与退出约定管理文本及输入监听资源，见 INPUT-REQ-007。

HTML 原型提供页内演示，Tauri 桌面应用负责实际 Windows 输入。具体结构见[领域设计](design.md)，真实 RDP 接收按[人工验收说明](../../../tests/manual/rdp.md)验证。
