# Domain 设计

## 领域模型

本领域围绕待输入文本、目标输入位置和输入任务组织，术语定义见[项目术语表](../../project/glossary.md)。

- 文本在编辑区准备，两种启动方式共用发送与中止规则。
- 输入任务包含启动前的等待和实际发送阶段，以 Rust 维护的任务状态为依据。
- 目标程序拥有输入控件及键盘焦点，工具向当前焦点发送事件。
- 单任务、文本与设置快照遵循[首版需求](requirements.md)。

确认与实现状态：技术职责和界面视觉基准已确认。桌面任务、系统输入与通信具有对应实现及本地自动验证，实际 RDP 接收按[人工验收说明](../../../tests/manual/rdp.md)验证。

## 实现结构

界面评审原型位于 [prototypes/key-relay.html](../../../prototypes/key-relay.html)，使用独立 HTML、CSS 和 JavaScript 演示编辑、设置、关于页、离线许可证及任务状态。原型说明和检查入口见 [prototypes/README.md](../../../prototypes/README.md)。

原型只向页面内测试框写入文本，桌面应用采用下述技术方案。界面行为约定见 INPUT-REQ-006，确认状态见[领域需求](requirements.md)。

### 界面视觉基准

本节定义桌面应用与原型的当前视觉规则，作为界面开发和验收依据。原型独立演示布局与页面内交互，系统窗口操作及输入由桌面应用验证。

界面验证覆盖浏览器 100%／150% 页面缩放，以及 Windows 150% 系统缩放下的 600px、390px、320px 窗口。Windows 100% 系统缩放待按[Windows 验收说明](../../../tests/manual/windows.md)检查。

#### 布局规则

- 界面采用浅色、紧凑的工具窗口样式，使用直角控件、细边框和有限的分隔线。按钮、页签、输入框、下拉框及数值控件外框的圆角均为 0。
- 从上到下排列标题区、输入／设置／关于页签、内容区、底部操作区。
- 输入页依次展示编辑框、字符数与文本说明。编辑框内显示占位提示“在此输入或粘贴文本…”，无障碍名称为“待输入文本”。底部左侧为状态文字，右侧依次为“开始输入”“清空”。
- 设置页的标题和“恢复默认”同行。下方依次为等待时间、快捷键、字符间隔，末尾显示中止规则。
- 桌面宽度下，设置项左侧为名称和说明，右侧控件统一宽度。秒和毫秒单位位于数值控件内部右侧。
- 相同视口宽度、文本和设置状态下，切换页签保持整体高度一致。调整编辑框高度后仍满足此规则。编辑框填充共享面板的剩余高度，字符信息紧邻底部操作区。
- 设置与关于页隐藏输入页的状态文字和操作按钮，并保留维持页签等高所需的布局空间。隐藏区域退出键盘焦点顺序。
- 状态文字共用一个位置，展示操作说明、倒计时提示、发送进度或结束结果。各状态使用相同的字体、字号、字重、行高、间距和排列方式，仅文本内容与整段文字颜色随状态变化。
- 状态区至少预留两行文字高度，较长文字允许继续换行。文字在预留高度内垂直居中；横向布局下，单行或多行提示的整体垂直中心与按钮组一致。
- 开始按钮右侧紧邻清空按钮。开始按钮在预留区域内靠右，倒计时长文案使用该区域，清空按钮和状态区的位置保持一致。
- 操作按钮共用尺寸、字体、直角边框及焦点规则。开始按钮采用蓝底白字表达主操作，清空、恢复默认、返回关于等次级按钮采用浅灰配色。
- 输入与设置内容高度随错误提示、文字换行和编辑框调整而变化；窗口总高度由共享面板内容决定。关于和许可证内容在面板内部滚动，保持三个页签的整体高度一致。

#### 状态与可访问性

- 空闲、等待释放、倒计时、输入进度、完成、中止和错误提示均使用普通文本，整段采用 13px 字号、400 字重和 1.7 行高。
- 等待释放、倒计时和发送进度提示使用蓝色，完成提示使用绿色，空闲、取消和中止提示使用中性灰。颜色作用于整段提示，状态同时保留明确文字。
- 错误提示、字段错误文字和无效数值控件边框使用同一错误色。
- 字段错误位于对应设置项下方，横跨该行。修正或恢复默认后隐藏错误。
- 焦点轮廓宽 2px。文本编辑框、设置数值框和快捷键下拉框采用 -2px 偏移，沿原有边界向内绘制，聚焦前后外边界及布局尺寸保持一致。数值框轮廓包围包含单位的整个控件。
- 标题栏按钮的焦点轮廓内偏移 3px，其余控件外偏移 2px。
- 页签选中状态通过边框、背景和文字颜色共同表达。
- 禁用状态保留控件尺寸，停止悬停和按下效果。相关禁用时机见 INPUT-REQ-006。
- 正文提示采用正式操作用语。例如倒计时提示为“等待输入，请在倒计时结束前选择输入位置”。

#### 关于页

- 左侧展示 48×48px 应用图标，右侧为 18px、400 字重的 Key Relay 名称及 12px 中性灰版本信息。版本由 Tauri `getVersion` 读取，旁边显示“Windows 64 位”。
- 用途说明为“将准备好的文本作为键盘输入发送到目标位置，适用于限制剪贴板粘贴的远程桌面会话。”正文和链接为 13px，窄窗口允许换行。
- 用途说明之后展示应用更新区域，再以细分隔线分开支持链接。支持区依次展示项目主页、使用说明、问题反馈；下一行显示联系邮箱。
- 更新区域包含检查按钮、自动检查开关、当前状态、更新说明及当前阶段操作。检查按钮沿用次级按钮，下载与安装使用主按钮。说明以纯文本显示，较长说明在 100px 高度内滚动。
- 安装就绪后提供页内确认，提示重启清除文本，并提供“暂不安装”和“确认安装并重启”。离开关于页时取消确认。
- 有新版本或安装就绪时，关于页签增加 5px 蓝色标记。更新事件保持当前页签及焦点，任务启动规则继续有效。
- 外部链接通过 Tauri Opener 的 `openUrl` 交给系统默认应用。主窗口的 `opener:allow-open-url` 权限只允许下表地址。
- 链接使用 `#326798`，悬停显示下划线，键盘焦点采用公共轮廓。版本读取和链接打开失败显示错误色提示，重试保留面板状态。
- 底部显示 12px 中性灰版权文字“© 2026 sunnyx11”及 MIT 许可证按钮。许可证从仓库 `LICENSE` 打包完整文本，支持离线读取、换行和面板内滚动。
- 许可证视图提供“返回关于”按钮。切换视图后内容回到顶部，进入时聚焦返回按钮，返回时聚焦许可证按钮。
- 页签切换和活动任务行为遵循 INPUT-REQ-006；从关于页进入活动任务时仅切换展示面板，保持目标程序焦点。

#### 应用图标

- Windows 应用图标采用 B「分离结构」：竖笔与两条相连斜笔组成 K，中间保留间隙，斜笔使用圆角线端。
- 字形颜色为 `#326798`，圆角底色为 `#F1F4F7`，外部区域透明。
- Windows 资源为 `src-tauri/icons/icon.ico`，包含 16、20、24、32、36、40、48、64、256px 九种尺寸。各尺寸分别设置笔画坐标、线宽与间隙，竖笔的直边位于整数像素边界。
- `scripts/generate-icons.mjs` 定义各尺寸的绘制参数。运行 `npm run icons` 在目标尺寸绘制各帧并生成 ICO，同时输出 256px 矢量图 `src-tauri/icons/icon.svg`。
- 程序、NSIS 安装程序和卸载程序通过 Tauri 配置引用同一 ICO，构建脚本跟踪 ICO 文件的变化。自定义标题栏展示应用名称及窗口操作按钮。

#### 原型与桌面窗口边界

- 网页外部背景、居中留白、评审标签及下方演示区仅用于原型展示。
- 原型图钉演示选中状态，窗口按钮控制页面内的折叠、宽度和显隐，标题双击切换展示宽度。Windows 系统置顶、拖动及窗口生命周期由桌面应用验证。
- 原型关于页内嵌版本示例、应用 SVG 图标与 MIT 全文，项目链接由浏览器打开。元数据读取和系统链接调用的错误状态由桌面应用验证。
- 原型通过固定数据演示安装版、独立 EXE、无更新、检查失败、签名失败和安装启动失败。模拟安装清除文本并保留当前页内设置，实际签名和安装由桌面验收验证。
- 自定义标题栏高 28px，在所有宽度下展示 Key Relay 名称及图钉、最小化、最大化／还原、关闭按钮。名称左侧保留 14px 内边距，名称所在区域支持拖动。32×27px 的按钮区域与窗口拖动区域分开。
- 四个窗口图标使用统一的 16×16 坐标和画布，线宽为 1px。最小化横线、最大化方框、关闭交叉线在画布内居中；图钉围绕画布中心旋转，针尖略长以保留辨识度。按钮内边距为零，图标居中。
- 普通窗口图标使用中性灰，悬停时使用正文色；置顶选中保持蓝色，禁用采用禁用色，关闭按钮悬停时使用错误色背景和白色图标。
- 图钉通过 Tauri 的 `isAlwaysOnTop` 和 `setAlwaysOnTop` 读取、设置窗口层级，设置权限限定于主窗口。置顶时使用蓝色背景和竖直图钉，普通状态图钉倾斜；`aria-pressed`、可访问名称和提示文字同步表达状态。
- 图钉在初始化、设置处理中以及活动任务期间禁用。读取或设置失败的错误文字位于标题栏下方，在三个页签均可见，点击图钉重试。
- 置顶的生命周期和任务操作约束见 INPUT-REQ-006、INPUT-REQ-007。
- 普通窗口及最大化还原后的窗口高度由内容决定，底部操作区之后紧接窗口边界。
- 原型外框边线和阴影用于展示窗口轮廓，Windows 窗口装饰由所采用的窗口方案决定。
- 视觉基准约束最终布局与样式效果。页签等高等规则的具体 CSS 实现可以按组件结构选择。

## 数据与接口

已确认的通信职责：

- React 将准备好的文本、设置及按钮操作提交给 Rust；全局快捷键事件在 Rust 侧处理。
- Rust 向 React 通知倒计时、输入中、完成、中止及错误状态，React 更新展示。
- 输入任务以 Rust 状态为依据。界面失去焦点后，任务继续由 Rust 驱动；WebView 中的计时器仅用于界面效果。

### 命令与状态契约

- `get_snapshot`：读取设置、任务状态及快捷键注册错误。
- `sync_draft`：提交 `{ revision, text, settings }`；仅接受更新的版本，设置可为无效草稿，启动时执行校验。
- `start_task`：接收同一草稿结构，固定快照并启动按钮倒计时。
- `cancel_task`：结束当前准备或发送任务。
- `save_settings`：验证并保存 `{ delaySeconds, intervalMs, shortcut }`，返回完整快照；快捷键注册失败单独反馈。
- `relay-state`：发送完整快照。快照包含递增 `sequence`、任务 `phase`、`sent`、`total`、`remainingSeconds`、`message`、有效 `settings`、`shortcutError`、`interactionBlocked`。
- `interactionBlocked` 在中止鼠标按钮释放前保持操作控件禁用。页面记住按下时禁用的控件，抑制同一次点击产生的启动、清空、置顶或关于页切换操作。

示例：按钮启动输入 `{"revision":2,"text":"ab","settings":{"delaySeconds":5,"intervalMs":50,"shortcut":"F8"}}`，返回快照 `{"sequence":3,"phase":"countdown","sent":0,"total":2,"remainingSeconds":5,"message":"等待输入，请在倒计时结束前选择输入位置","settings":{"delaySeconds":5,"intervalMs":50,"shortcut":"F8"},"shortcutError":null,"interactionBlocked":false}`。

前端先订阅事件，再查询快照；按序号接受更新。编辑同步、有效设置保存及按钮启动串行发送，按钮启动显式携带当前草稿。保存设置作用于后续任务，当前任务使用启动时的快照。文本只存储在进程内存。配置与空文本错误通过命令错误或独立提示反馈，保持任务阶段。

Rust 任务线程串行处理命令、键鼠事件和计时。Windows 监听运行在拥有消息循环的独立线程，回调仅记录必要按键状态并发送事件。发送单元间的等待可被命令或中止事件唤醒。

### 更新命令与安装互斥

更新状态独立于输入任务快照，由 Rust 管理并按 `sequence` 排序。前端先订阅 `update-state`，再查询快照。自动检查计时属于更新发现，输入任务计时继续由 Rust 驱动。

| 命令 | 输入 | 输出 |
| --- | --- | --- |
| `get_update_state` | 无 | 完整更新快照 |
| `set_update_preference` | `{"autoCheck":false}` | 保存后的完整更新快照 |
| `check_update` | 无 | 版本检查后的完整更新快照 |
| `download_update` | 无 | 验签后的就绪状态或可重试错误状态 |
| `install_update` | `{"confirmed":true}` | 安装启动失败或活动任务延后时的快照；成功接管时退出进程 |

快照示例：

```json
{"sequence":3,"phase":"available","installed":true,"autoCheck":true,"version":"0.3.0","notes":"改善输入体验。","downloaded":0,"total":null,"message":""}
```

更新阶段为 `idle`、`checking`、`current`、`available`、`downloading`、`ready`、`installing`、`error`。下载失败返回 `available` 并显示原因；只有签名验证成功后才进入 `ready`。下载包字节与 Updater 实例保留在 Rust，前端只取得进度和元数据。

- 更新清单地址固定为 GitHub 最新正式 Release 的 `latest.json`。清单和下载请求限定 HTTPS，检查超时 30 秒、下载超时 600 秒，进度事件最多约每 100 毫秒发送一次。
- `scripts/package.mjs` 将构建变量 `TAURI_UPDATER_PUBLIC_KEY` 注入 Tauri 更新配置，CLI 和客户端使用同一公钥。签名及附件格式见[版本发布](../../release.md)。
- 当前用户卸载项 `Software\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\Key Relay` 的 `InstallLocation` 与当前 EXE 规范化位置匹配时视为安装版。
- 更新偏好保存在配置目录 `updates.json`，格式为 `{"autoCheck":true}`。解析失败时显示提示并关闭自动检查，显式设置后恢复保存。输入设置文件保持原结构。
- 安装准备通过 `PrepareUpdate` 进入单任务线程。任务空闲且鼠标释放保护结束后设置安装保留状态，停止系统钩子并注销快捷键。`Engine::start` 对按钮与快捷键执行共同检查。
- 前端安装操作先串行保存最近有效输入设置。安装期间关闭请求保持应用运行，直到安装程序接管或准备失败恢复。
- Updater 使用 NSIS `passive` 模式与安装后重启。启动失败通过 `ResumeUpdate` 恢复钩子和快捷键，再释放安装保留状态；失败原因保留在更新区域。

## 状态变化与异常处理

以下为 INPUT-REQ-005 引用的状态模型。启动、取消和中止条件见 INPUT-REQ-002、INPUT-REQ-003、INPUT-REQ-004。

| 状态 | 含义 | 结束条件 |
| --- | --- | --- |
| 空闲 | 没有活动任务 | 快捷键或按钮启动 |
| 等待释放 | 等待开始组合键全部释放 | 进入输入中，或启动取消 |
| 倒计时 | 按钮启动后的等待阶段 | 进入输入中，或倒计时取消 |
| 输入中 | 正在发送文本 | 完成、人工中止或发送失败 |
| 已完成 | 全部文本已发送 | 新的独立启动操作 |
| 已中止 | 本次准备或发送任务结束，剩余内容取消 | 新的独立启动操作 |
| 失败 | 本次输入发送发生可检测错误 | 修正后重新启动 |

准备阶段的取消与发送阶段的中止均结束本次任务。是否保留实际按键效果、允许下一次独立启动以及如何展示错误，由相应需求条目定义。

## 跨域协作

当前仅有文本自动输入领域。目标程序作为外部接收方，拥有焦点及输入处理行为。

## 技术决策与约束

技术选型采用[项目上下文](../../project/context.md#技术环境与依赖)中的 Tauri 2、Rust、React、TypeScript 及相关工具。Windows 本地输入具有受控接收验证，远程兼容范围依据实际 RDP 验收。

### 职责分工

- React 展示编辑内容、倒计时及任务状态，向 Rust 发出操作请求。
- Rust 负责输入任务、倒计时、发送间隔、系统级键鼠监听、中止判断及资源释放。
- 全局快捷键由 Tauri 插件注册，模拟输入通过 `windows` crate 调用 Windows `SendInput`。
- 人工中止使用系统级键鼠监听，React 页面事件用于工具自身的界面交互。

### 系统输入与监听

- 中文和普通字符使用 Unicode 输入事件，补充平面字符按 UTF-16 代理对发送；Enter 和 Tab 使用虚拟键按下及释放。
- 结合注入标记与工具自身的事件标识识别模拟输入，避免自身事件触发中止。其他程序注入的事件和特殊输入设备行为需要验证。
- 开始快捷键的释放通知与实际按键状态共同参与判断，发送前确认组合键全部释放。
- 系统监听回调保持短时执行，发送任务在可中止的等待及发送边界检查停止状态。
- 已提交系统的事件无法撤回，任务中止取消尚未提交的内容。
- 系统监听使用低级键盘和鼠标钩子，线程组织与通信规则见本文件的数据与接口。

### 兼容与部署

- `SendInput` 受 Windows 完整性级别限制，工具向更高权限目标程序发送输入可能失败。
- 发送返回值无法单独确认目标控件完整接收文本，也无法单独确认失败是否由权限隔离造成。
- 中文、Enter、Tab、输入法状态及人工中止需要在实际 Windows 目标程序中验证。
- 面向当前用户的 NSIS 安装程序在缺少 WebView2 时下载并安装运行时。
- 支持本地 Windows 10／11 x64，默认普通权限。RDP 实际兼容性保留人工验收，详见[项目上下文](../../project/context.md#已知限制)。
