# Domain 需求

本文件维护已确认的首版目标需求。实现及验证状态单独说明。

**实现与验证状态**：桌面应用实现文本编辑、草稿保存与启动恢复、历史全文查看及独立恢复、单实例唤起、目标记录与回点、任务控制、设置保存、系统输入与监听。自动测试覆盖用户数据目录与文件缺失默认值、本机文本读写、历史交互、负坐标换算、任务及界面。浏览器检查覆盖按钮任务、文本及界面交互。当前构建的系统实时按键查询、Windows 目标回点与接收、Esc 和物理鼠标中止、安装失败后的监听恢复、多显示器及缩放和 RDP 兼容性待按 [Windows 验收说明](../../../tests/manual/windows.md)与 [RDP 验收说明](../../../tests/manual/rdp.md)人工检查。

**确认状态**：下列处理规则已确认。首版运行在本地 Windows 10／11 x64，通过当前焦点的 RDP 客户端向远程服务器输入，首个验收客户端为 `mstsc.exe`。自定义标题栏、当前用户安装程序、按需联网安装 WebView2 均为首版要求。

字符计数与发送进度按 Unicode 标量计算，CRLF 合并为一个换行单元。表情和组合字符允许发送，其实际接收兼容性依据人工验证结果说明。

## INPUT-REQ-001 文本准备

### 功能说明

提供多行文本编辑区域，使用者可以手动输入或粘贴需要发送的文本。

### 处理规则

已确认：

- 在工具中填写待输入文本，并按文本顺序发送内容。
- 保留大小写、空格、标点及换行含义。
- 每次启动时固定本次文本和设置，后续编辑及设置变化作用于下一次任务。
- 任务结束后保留编辑框中的原始文本。草稿保存、启动恢复及发送历史遵循 INPUT-REQ-007。
- 空字符串阻止启动，提示“请先填写文本”；仅含空格或换行的文本按原内容处理。
- 首版支持中文、英文字母、数字及常用中英文标点。表情和复杂组合字符允许发送，实际兼容性由人工验证。
- CRLF 与 LF 均识别为一次换行并发送 Enter；制表符发送 Tab。
- 使用说明列明 Enter 和 Tab 的效果由目标程序决定，可能提交表单或切换输入控件。
- “清理”仅在手动触发时删除每行末尾的普通空格 U+0020 和制表符 U+0009，包括末行。缩进、行内空格、换行、空行及其他 Unicode 空白字符按原内容保留。
- 编辑框沿用浏览器的换行规范化；清理保持换行数量和位置。
- 清理后的内容成为当前待输入文本，开始按钮使用最新草稿。原生编辑历史及反馈遵循 INPUT-REQ-006。

### 数据示例

在兼容输入框中，准备文本 `Hello 123，测试。`，完整发送后的期望内容为 `Hello 123，测试。`。

在使用 Enter 换行的多行输入框中，准备文本 `第一行\n第二行`，目标内容为：

```text
第一行
第二行
```

### 边界情况

| 输入或条件 | 结果或建议结果 |
| --- | --- |
| 空字符串 | 提示填写文本，保持空闲 |
| 三个空格 | 发送三个空格；手动清理后为空字符串 |
| `"\t第一行  \t\n  第二行 \t\n\n末行  "` | 清理后为 `"\t第一行\n  第二行\n\n末行"` |
| `" \t\n\t\n"` | 清理后为 `"\n\n"`，保留两次换行 |
| `"a\u00a0  "` | 清理后为 `"a\u00a0"`，保留不换行空格 |
| CRLF 或 LF | 各对应一次 Enter 操作 |
| 文本包含 Tab | 发送 Tab，目标程序可能切换控件 |
| 表情或复杂组合字符 | 允许发送，实际接收结果由人工验收 |
| 中文或英文输入法状态下发送中文 | 在兼容目标程序中检查实际字符输出 |

## INPUT-REQ-002 按钮启动与按键状态

### 功能说明

通过“开始输入”按钮启动任务。启动释放判断采用 Windows 当前的修饰键和鼠标按钮状态。目标激活与回点遵循 INPUT-REQ-003。

### 处理规则

已确认：

- 开始按钮是任务启动入口，启动时固定本次文本、字符间隔及记录目标。
- 准备阶段实时查询 Ctrl、Alt、Shift、Win 和鼠标按钮，最多等待 2 秒释放。首字符提交前再次查询。
- 系统当前状态决定是否已释放。遗漏的键盘释放事件及应用持续运行时间保持后续启动可用。
- 普通字符、方向键及 F8、F9、F10、F22 等功能键的持续状态允许启动。`Ctrl+Alt+F8/F9/F10` 按系统和目标程序的原有语义处理。
- 等待释放期间，取消按钮、Esc 或实际鼠标按下结束本次准备。普通键盘操作保持任务状态。
- 等待超时后发送数量为零。释放修饰键和鼠标按钮后，新的按钮操作可重新启动。
- 同次中止鼠标操作全部释放后，操作控件恢复，规则见 INPUT-REQ-004、INPUT-REQ-006。

### 数据示例

文本为 `abc`，已记录目标输入框。返回工具后点击“开始输入”，系统报告修饰键和鼠标按钮已释放时，激活并回点记录位置，随后依次发送 `a`、`b`、`c`。

### 边界情况

| 条件 | 结果 |
| --- | --- |
| 修饰键或鼠标按钮仍按住 | 最多等待 2 秒，超时取消且发送数量为零 |
| 先前收到修饰键按下事件、释放事件遗漏，系统当前已释放 | 允许正常启动 |
| 超时后全部释放并再次点击开始 | 创建新任务，从原文开头发送 |
| 等待期间按 Esc 或实际按下鼠标 | 取消准备，发送数量为零 |
| 普通字符、方向键或功能键持续按住 | 按系统修饰键和鼠标按钮状态判断启动 |
| 首字符前再次按住修饰键 | 取消本次任务，发送数量为零 |

## INPUT-REQ-003 记录目标与启动

### 功能说明

记录最近一次外部鼠标左键点击的屏幕坐标与窗口。点击“开始输入”后，激活并回点记录位置，再发送文本。

### 处理规则

已确认：

1. 空闲时记录外部窗口的物理左键点击。记录包含物理屏幕坐标和顶层窗口。工具内部点击、桌面、任务栏及模拟鼠标事件保留已有记录。
2. 输入页使用单行摘要“已记录输入位置”。悬停或键盘聚焦状态文字时，详情浮层显示窗口标题和物理坐标。浮层允许换行，保持主窗口高度；Esc 可收起详情。此记录表示点击点，输入控件与光标由目标程序处理。
3. 尚未记录时禁用开始按钮，启动命令返回“请先点击外部输入位置”。窗口失效、最小化或几何信息变化时显示“目标已失效，请重新选择输入位置”。
4. 按钮启动固定文本、设置和目标。进入目标激活阶段，按钮显示“取消输入”，设置页签禁用。
5. 启动操作释放后，校验窗口与显示器信息，激活目标窗口，确认记录点属于该窗口，再模拟一次左键点击。短暂等待目标处理点击后发送首字符。
6. 目标激活期间，取消按钮、Esc 和实际鼠标按下均结束准备。工具自身模拟点击保持任务执行。
7. 输入阶段遵循 INPUT-REQ-004。按钮及按键状态规则见 INPUT-REQ-002。

坐标与启动检查：

- 使用整个虚拟桌面的物理坐标，支持左侧、上方显示器的负坐标及各显示器不同缩放比例。
- 启动前按 INPUT-REQ-001 校验文本，按 INPUT-REQ-005 校验字符间隔。
- 最多等待 2 秒释放 Ctrl、Alt、Shift、Win 和鼠标按钮，判断采用实时系统状态。超时结束准备，普通字符、方向键及功能键允许启动。
- 检查窗口句柄、所属进程与线程、可见及启用状态、位置、尺寸、DPI、记录点所在显示器与虚拟桌面范围。
- 窗口失效、最小化、窗口或相关显示配置变化、激活失败或记录点被遮挡时清除记录，提示重新选择。本次任务发送字符数为零。
- 首字符发送前再次确认目标窗口、点位归属及按键状态。
- 页面滚动、远程页面布局变化或控件移动后需要重新点击目标。坐标记录只覆盖本地窗口与显示几何。
- 记录只驻留内存，重新启动应用后重新选择。输入设置为字符间隔；文本保存选项见 INPUT-REQ-007。

### 数据示例

文本为 `abc`，字符间隔为 50 毫秒。目标输入框位于左侧副屏：

| 操作 | 状态与结果 |
| --- | --- |
| 点击外部输入框 `(-900, 240)` | 显示“已记录输入位置”，详情提供窗口标题与坐标 |
| 返回 Key Relay 编辑文本、清理或调整设置 | 保留记录位置 |
| 点击“开始输入”并释放启动操作 | 激活目标窗口并回点 `(-900, 240)` |
| 目标处理点击后 | 顺序发送 `a`、`b`、`c` |
| 全部提交后 | 显示已完成，保留原文 |

### 边界情况

| 条件 | 结果 |
| --- | --- |
| 尚未记录外部位置 | 开始按钮禁用，启动命令提示选择位置，发送零字符 |
| 点击工具编辑区、清理、清空或设置 | 保留记录目标 |
| 点击另一外部应用窗口 | 使用新的窗口和点击坐标 |
| 目标激活期间点击鼠标或按 Esc | 取消任务，发送字符数为零 |
| 启动时修饰键或鼠标按钮持续按下 | 等待释放，超时取消 |
| 目标窗口移动、缩放、关闭或最小化 | 清除记录，要求重新选择 |
| 记录点被置顶窗口遮挡 | 结束准备，要求重新选择 |
| 目标位于负坐标副屏或不同 DPI 显示器 | 按物理屏幕坐标回点 |
| 相关显示器断开、排列或缩放改变 | 清除失效记录，要求重新选择 |
| 远程页面滚动但本地窗口位置保持 | 使用者重新点击实际输入位置 |

## INPUT-REQ-004 文本发送与人工中止

### 功能说明

按钮启动后按顺序发送文本，Esc 和鼠标按下中止任务。

### 处理规则

已确认的发送阶段事件规则：

| 事件 | 行为 |
| --- | --- |
| 鼠标移动 | 继续输入 |
| 鼠标按下 | 停止输入 |
| Esc 按下 | 停止输入 |
| 普通字符、方向键、修饰键及无关功能键 | 继续输入，目标程序处理原有按键效果 |
| 工具自身模拟的键盘和鼠标事件 | 继续输入 |
| 全部文本发送完毕 | 结束任务 |

焦点行为采用已确认的简化方案：

- 事件发送到当时的键盘焦点位置，省去输入控件失焦检测。
- 鼠标按下或 Esc 执行中止。普通键盘操作继续任务，可能改变光标、内容或焦点，后续事件发送到当时的焦点。
- 其他程序主动取得焦点，且未发生鼠标按下或 Esc 中止事件时，继续输入，后续文本可能进入新位置。
- 发送阶段按当前焦点继续处理；目标回点规则见 INPUT-REQ-003。

事件处理细则：

- 鼠标按下覆盖左键、右键、中键及侧键。键盘中止操作为 Esc。
- 滚轮滚动继续输入，按下滚轮中键停止输入；仅松开按键或鼠标按钮保持任务状态。
- 工具根据注入标记与自身事件标识识别发送事件，自身事件继续任务。外部普通键盘事件继续任务，外部 Esc 事件执行中止规则。
- 检测到中止后取消尚未发送的内容，并中断字符间等待。
- 已交给系统的事件可能继续被处理，已输入内容保留。
- 中止操作保留原有效果，例如点击改变焦点、Esc 交由目标程序处理。普通人工输入可能与自动文本混合。工具内原本禁用按钮的保护规则见 INPUT-REQ-006。
- 中止后保持结束状态；新的独立启动从文本开头输入。首版省去暂停与续输功能。
- 同一时间仅有一个准备中或发送中的任务。重复启动请求按所处阶段取消或中止，按钮启动规则见 INPUT-REQ-002、INPUT-REQ-003。
- 输入发送失败时停止，并显示能够检测到的错误。

### 数据示例

输入文本为 `abcdef`。在目标收到 `abc` 且后续事件尚未发送时，使用者点击另一输入框：任务中止，第一个输入框保留 `abc`，剩余 `def` 取消。

如果部分后续事件已提交系统，其处理位置由焦点切换时机决定，已提交事件无法撤回。

再次独立触发开始时，完整待发送文本仍为 `abcdef`。

### 边界情况

| 条件 | 结果或建议结果 |
| --- | --- |
| 持续移动鼠标 | 连续发送文本 |
| 点击同一输入框中的其他位置 | 因鼠标按下而中止 |
| 点击另一个输入框 | 因鼠标按下而中止；已提交事件可能继续处理 |
| 按 Esc | 中止，保留已发送数量，目标程序处理 Esc 原有效果 |
| 按 Ctrl、方向键、退格键、普通字符键或无关功能键 | 继续任务，实际操作仍生效，内容可能与自动输入混合 |
| 工具发送自身的模拟事件 | 任务持续执行 |
| 外部程序自动取得焦点 | 按当前简化规则继续向新焦点发送 |
| 原输入框保留已发送内容后重新启动 | 从文本开头发送，可能与已有内容重复 |

## INPUT-REQ-005 输入速度与任务状态

### 功能说明

通过字符间隔设置控制发送速度，并展示任务准备、发送及结束状态。

### 处理规则

已确认：

- 按顺序逐个发送字符，字符之间使用固定间隔。
- 默认字符间隔为 50 毫秒，允许 10～1,000 毫秒的整数。
- 无效设置阻止启动并提示修正。更慢速度用于适应接收较慢的目标程序，实际接收能力需要验证。
- 发送成功表示事件已提交，目标完整接收需要另行检查。
- 状态模型采用[领域设计中的状态定义](design.md#状态变化与异常处理)，包含空闲、目标激活、输入中、已完成、已中止和失败。
- 配置和空文本错误保持原任务状态。
- 状态通知保持目标程序的焦点。

已确认的界面反馈见 INPUT-REQ-006。

### 数据示例

文本 `abc`，字符间隔 50 毫秒，启动条件满足时发送 `a`，间隔后依次发送 `b`、`c`。全部事件提交后显示已完成，已发送字符数为 3；目标接收结果由兼容性验证确认。

### 边界情况

| 条件 | 建议结果 |
| --- | --- |
| 字符间隔为 10 或 1,000 毫秒 | 通过范围校验 |
| 字符间隔为 0、9、1,001、1.5 或空值 | 提示设置错误，阻止启动 |
| 目标程序处理速度低于发送速度 | 允许调慢间隔，实际接收效果需验证 |
| 部分发送后失败 | 停止发送，展示能够检测到的错误 |

## INPUT-REQ-006 界面操作与反馈

### 功能说明

通过输入、历史、设置和关于四个页面完成文本编辑、历史恢复、清理、清空、参数调整、任务状态查看及项目信息查阅。布局、配色和尺寸使用[界面视觉基准](design.md#界面视觉基准)，验收遵循[项目测试要求](../../project/principles.md#测试要求)。

### 处理规则

已确认：

- 输入页内容区域为多行编辑框。底部左侧为状态，右侧依次为字符数、清理、清空、开始输入；窄窗口采用状态在上、操作区在下并靠右的排列。
- 开始按钮在目标激活期间承担取消操作，文案与页签行为见 INPUT-REQ-003。实际输入期间禁用开始按钮，文案为“输入中…”。
- 空文本禁用清理和清空。初始化、操作提交、目标激活、输入、安装准备及中止鼠标释放保护期间，清理和清空保持禁用。
- 输入期间实际鼠标按下仍按 INPUT-REQ-004 中止。点击原本禁用的操作按钮时，该次点击只中止任务并保留原文；按钮恢复后需再次独立操作。
- 清理按文本末尾向前逐行删除，`Ctrl+Z` 逐行撤销，`Ctrl+Y` 逐行重做。清空支持整体撤销和重做。后续编辑继续使用原生历史。
- 清理成功提示“已去除行尾空格，可按 Ctrl+Z 逐行撤销。”。没有匹配内容时提示“当前文本没有行尾空格。”，保留已有编辑历史。
- 清理过程中删除失败时停止后续操作，保留已完成的编辑，同步实际文本并显示“去除行尾空格未完成，请重试”。
- 字符数随清理、清空、撤销、重做及普通编辑更新。清空提示说明撤销方式。
- 清理和清空在悬停及键盘焦点时显示用途提示；可访问名称固定为按钮名称，详细描述说明操作范围及撤销方式。
- 设置项错误显示在对应参数下方，修正或恢复默认后消失。启动时有无效设置则定位到该项。
- 输入期间在现有说明位置显示已发送数量与总数，并提示“按 Esc 或点击鼠标停止”；结束后显示完成或中止结果。
- 设置页的中止说明为“输入期间，鼠标移动和普通按键继续；按 Esc 或点击鼠标停止。”
- 任务结束后按钮恢复为“开始输入”。

## INPUT-REQ-007 本地数据与运行生命周期

### 功能说明

约束文本及设置的保留方式、启动与退出行为和输入监听的数据使用。运行环境和兼容范围见[项目上下文](../../project/context.md#已知限制)。

### 处理规则

已确认：

- 软件启动时处于空闲状态。同一 Windows 会话内仅有一个应用实例；重复启动在设置、文本存储和输入资源初始化前通知已有进程并退出。已有窗口最小化时先还原，随后显示并请求前台焦点，保留编辑内容、页签及置顶状态。
- 程序运行期间显示通知区域图标，主体大小与相邻应用图标接近，并保留应用图形与颜色。左键单击打开窗口；右键菜单依次提供“打开窗口”“重置位置”“退出应用”。
- 标题栏关闭按钮、Alt+F4 和任务栏“关闭窗口”隐藏主窗口，进程继续运行。最小化按钮保留最小化行为。
- 从通知区域打开窗口时显示并还原主窗口，保留编辑内容、页签和置顶状态。重置位置保留普通窗口的逻辑尺寸，将窗口移至主屏工作区中央并打开。
- 窗口启动时默认置顶，图钉切换结果仅在当前运行期间保留。最小化与还原保持当前置顶状态，退出后重新打开恢复默认置顶。
- 正常退出及安装更新前保存普通窗口的还原大小和位置，启动时在首次显示前恢复。最大化或最小化退出后以普通窗口恢复，异常终止使用最近一次成功保存的记录。
- 位置使用物理屏幕坐标，客户区大小使用逻辑尺寸。恢复时按当前显示器倍率计算完整原生窗口矩形；矩形完整位于任一显示器工作区时保留位置，负坐标有效。
- 窗口部分超出工作区、完全移出或位于多屏空隙时，保留可用大小并在主显示器工作区居中。超过工作区的尺寸在最小 320×340 约束内缩小；工作区小于最小尺寸时保留最小尺寸，并让窗口顶部位于工作区内。
- 窗口状态缺失、损坏或尺寸无效时使用默认 600×340 并居中。窗口状态读取及保存失败记录诊断信息，启动和退出继续执行。
- 发送过程保留系统剪贴板内容。
- 文本仅在本机处理，日志和错误提示省略待输入文本。
- 默认开启“保存并恢复上次编辑内容”和“保存历史输入记录”，偏好独立于字符间隔保存。
- 草稿包含最新编辑和未发送修改。编辑、粘贴、清理、清空、撤销、重做与历史恢复更新草稿；清空保存空字符串，历史保留。
- 启动读取完成前编辑框只读，成功后按草稿开关恢复文本。读取失败显示错误与重试，保留原文件。恢复文本保持空闲，发送仍需主动启动并重新选择外部目标。
- 任务通过首字符前校验、进入实际提交阶段时，后端记录本次冻结的完整原文。单字符任务、随后中止或发送失败的任务保留记录。准备阶段取消、普通编辑与历史恢复保持现有历史。
- 历史总上限默认 100 条，可在设置页配置为 1～10,000 的整数，置顶计入上限。新增时优先淘汰记录时间最早的未置顶记录，同时间按编号最小处理。置顶状态写入文本文件，旧数据缺少该字段时默认未置顶。
- 最大历史条数与文本保存选项一同持久化，现有文件缺少该字段时采用 100。点击“保存上限”后立即生效，关闭历史保存时仍可调整。
- 调低后现有记录超限时，点击“保存上限”后立即按相同淘汰顺序清理未置顶记录，保留置顶、草稿、其余归档顺序及下一编号。
- 上限小于当前置顶数量或数值无效时，显示字段错误并保留原设置和记录。
- 去重仅比较最近归档记录的完整原文，与显示排序和置顶操作分别处理。相同原文更新时间，保留编号及置顶状态；其他内容新增记录。
- 历史达到配置上限且全部置顶时，新文本跳过历史保存，保留已有记录及编号分配状态，输入任务正常执行。独立提示区持续显示容量说明，任务进度和结果继续显示；释放容量或关闭历史保存后收起提示。最近归档记录的相同文本仍可更新时间。历史展示和删除规则见 INPUT-REQ-006。
- 关闭保存选项后保留已有内容。草稿保存关闭时，后续编辑保持在当前进程，重新启动显示空编辑框；再次开启时保存当前编辑内容。历史保存关闭时停止新增记录，已有记录仍可恢复或清除。
- 用户数据目录为 `%USERPROFILE%\.key-relay\`，安装版与独立 EXE 共用该目录。文本与保存选项以明文保存为 `text.json`，输入设置保存为 `settings.json`，更新偏好保存为 `updates.json`，窗口状态保存为 `window-state.json`，文本独占锁为 `text.json.lock`。
- 新目录缺少文件时使用默认设置、空草稿和空历史；已有新目录文件继续生效。原 Windows 应用配置目录的文件保留原处，读取与保存均使用新目录。测试可通过 `KEY_RELAY_TEST_CONFIG_DIR` 指定隔离目录。
- 保存失败显示可重试提示，当前编辑内容与历史状态保留。选择通知区域“退出应用”时先停止任务，等待前端编辑同步队列、最近有效设置及文本写入；等待期间编辑只读。写入失败保持应用运行，显示主窗口并提示错误，恢复权限后可从通知区域再次选择退出。
- 安装进行中的关闭窗口和退出应用请求保持当前进程及窗口状态，按 INPUT-REQ-008 等待安装程序接管或准备失败恢复。
- 文本存储线程持有独占文件锁，保护文件写入；应用单实例规则在启动入口处理。
- 目标窗口信息及坐标仅驻留内存。
- 输入设置 `settings.json` 保存字符间隔 `intervalMs`。读取时忽略 `shortcut`、`delaySeconds` 等额外字段，保留有效字符间隔；保存时只写入当前字段。
- 退出软件时结束任务，释放输入监听资源。
- 系统按键状态仅用于启动释放检查，键盘事件仅用于 Esc 中止判断。鼠标事件用于目标记录、中止及同次点击释放保护。
- 发送失败的处理见 INPUT-REQ-004。

## INPUT-REQ-008 应用更新

### 功能说明

从 GitHub 最新公开正式版本检查更新。安装版提供签名下载和确认安装，独立 EXE 提供手动下载入口。首次完整升级验证状态见[版本发布](../../release.md#验证状态)。

### 处理规则

- 默认在启动完成 10 秒后检查，其后每 24 小时检查。关于页提供手动检查和自动检查开关，偏好独立保存。
- 检查仅获取版本与说明。发现更新显示页签标记和页内状态，保持当前页签和系统焦点。
- 关于页展示目标版本、更新状态、下载进度、错误提示及当前阶段操作。具体发布说明由 GitHub Release 提供，关于页省略正文。
- 相同、较低版本及预发布版本保持当前安装；网络或清单错误显示提示并可重试。
- 安装版由使用者确认下载，完整下载并通过公钥签名验证后显示安装入口。检查、下载分别保持单操作，任务可同时运行。
- 独立 EXE 显示正式 Release 下载入口，由使用者退出后替换文件。安装记录与当前 EXE 位置共同确定安装模式，识别失败时采用手动替换。
- 安装入口根据草稿保存选项提示重启结果。开启时说明安装前保存并在重启后恢复；关闭时说明本次未保存内容在重启后清除。每次安装请求需要独立确认，切换页签或任务启动会取消界面确认状态。
- 安装前等待最新草稿写入并保存最近有效设置。Rust 任务线程确认空闲后保留安装状态，阻止按钮启动，释放钩子后调用安装程序。
- 活动任务或中止释放保护期间延后安装，并保留当前进程内的已验证下载。安装启动失败时恢复原生资源，并显示重试信息。
- 安装程序接管后应用退出，成功安装后启动新版。新版从 INPUT-REQ-007 指定目录读取数据；草稿按保存开关恢复，有效设置、历史及更新偏好采用该目录中的文件。
- 下载结果只保存在当前进程内存。签名验证失败时清除下载结果并禁止安装。更新请求和诊断省略编辑文本。
- 0.1.0 通过手动安装升级至带更新模块的版本，后续安装版使用上述更新流程。

### 数据示例

当前安装版为 `0.2.0`，数据已保存于 `%USERPROFILE%\.key-relay\`，清单包含正式版本 `0.3.0` 及发布说明正文。自动检查后显示“发现新版本 0.3.0”和“下载更新”，发布说明正文仅在 GitHub Release 中提供；点击“下载更新”获取并校验安装包。选择“安装并重启”后确认重启提示，空闲时完成保存并执行安装。草稿保存开启时重启恢复编辑文本，关闭时编辑框为空；字符间隔、历史及自动检查偏好保持原值。

### 边界情况

| 条件 | 结果 |
| --- | --- |
| 检查或下载期间开始输入 | 输入任务继续由 Rust 处理 |
| 下载完成时任务仍活动 | 保留下载，任务结束后等待新的安装确认 |
| 确认安装与按钮启动相邻发生 | 任务线程按先后顺序处理；已有任务阻止安装，已有安装状态阻止启动 |

| 安装启动失败 | 恢复钩子和任务能力；恢复失败时显示具体错误 |
| 未配置构建公钥 | 显示配置提示，继续提供文本输入 |
