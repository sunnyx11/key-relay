# Domain 需求

本文件维护已确认的首版目标需求。实现及验证状态单独说明。

**实现与验证状态**：桌面应用实现文本编辑、任务控制、设置保存、系统输入与监听。任务和界面具有自动回归，受控 Windows 接收窗口验证本地输入及钩子清理。RDP 实际兼容性待人工验证，安装与系统环境验收见 [Windows 验收说明](../../../tests/manual/windows.md)。

**确认状态**：下列处理规则已确认。首版运行在本地 Windows 10／11 x64，通过当前焦点的 RDP 客户端向远程服务器输入，首个验收客户端为 `mstsc.exe`。自定义标题栏、当前用户安装程序、按需联网安装 WebView2 均为首版要求。

字符计数与发送进度按 Unicode 标量计算，CRLF 合并为一个换行单元。表情和组合字符允许发送，其实际接收兼容性依据人工验证结果说明。

## INPUT-REQ-001 文本准备

### 功能说明

提供多行文本编辑区域，使用者可以手动输入或粘贴需要发送的文本。

### 处理规则

已确认：

- 在工具中填写待输入文本，并按文本顺序发送内容。
- 保留大小写、空格、标点及换行含义。
- 每次启动时固定本次文本和设置，后续编辑及设置变化作用于下一次任务。
- 任务结束后保留编辑框中的原始文本。
- 空字符串阻止启动，提示“请先填写文本”；仅含空格或换行的文本按原内容处理。
- 首版支持中文、英文字母、数字及常用中英文标点。表情和复杂组合字符允许发送，实际兼容性由人工验证。
- CRLF 与 LF 均识别为一次换行并发送 Enter；制表符发送 Tab。
- 使用说明列明 Enter 和 Tab 的效果由目标程序决定，可能提交表单或切换输入控件。
- “清理”仅在手动触发时删除每行末尾的普通空格 U+0020 和制表符 U+0009，包括末行。缩进、行内空格、换行、空行及其他 Unicode 空白字符按原内容保留。
- 编辑框沿用浏览器的换行规范化；清理保持换行数量和位置。
- 清理后的内容成为当前待输入文本，按钮和全局快捷键均使用最新草稿。原生编辑历史及反馈遵循 INPUT-REQ-006。

### 数据示例

在兼容输入框中，准备文本 `Hello 123，测试。`，完整发送后的期望内容为 `Hello 123，测试。`。

在使用 Enter 换行的多行输入框中，准备文本 `第一行\n第二行`，目标内容为：

```text
第一行
第二行
```

### 边界情况

| 输入或条件 | 结果或建议结果 |
| --- | --- |
| 空字符串 | 提示填写文本，保持空闲 |
| 三个空格 | 发送三个空格；手动清理后为空字符串 |
| `"\t第一行  \t\n  第二行 \t\n\n末行  "` | 清理后为 `"\t第一行\n  第二行\n\n末行"` |
| `" \t\n\t\n"` | 清理后为 `"\n\n"`，保留两次换行 |
| `"a\u00a0  "` | 清理后为 `"a\u00a0"`，保留不换行空格 |
| CRLF 或 LF | 各对应一次 Enter 操作 |
| 文本包含 Tab | 发送 Tab，目标程序可能切换控件 |
| 表情或复杂组合字符 | 允许发送，实际接收结果由人工验收 |
| 中文或英文输入法状态下发送中文 | 在兼容目标程序中检查实际字符输出 |

## INPUT-REQ-002 全局快捷键启动

### 功能说明

工具处于后台时，使用者可以在目标输入位置通过全局快捷键启动任务。

### 处理规则

已确认：

1. 使用者填写文本，点击目标输入位置并确认光标。
2. 按全局快捷键后进入“等待释放”状态。
3. 等待启动组合键全部释放后发送第一个字符。启动组合键的按下和释放属于准备操作。
4. 发送阶段执行 INPUT-REQ-004 的统一中止规则。

快捷键配置与保护规则：

- 默认快捷键为 `Ctrl + Alt + F8`，提供 F8、F9、F10 三个组合选项。
- 注册失败时显示占用或注册错误提示，允许重新设置；按钮启动仍可使用。
- 工具自身处于前台时阻止快捷键启动，提示先选择目标位置。
- 等待释放期间按 Esc 或发生鼠标按下，取消本次启动；普通键盘操作保持等待。
- 启动检查包含 Ctrl、Alt、Shift、Win、鼠标按钮及本次所选功能键。无关功能键和普通字符的按下状态允许启动。
- 同一次快捷键操作由修饰键和当前选定功能键的按下及释放确定；无关按键保持新的独立操作可识别。
- 输入过程中再次按开始快捷键，仅停止当前任务。该次按键操作结束后，新的独立启动操作才创建下一次任务。
- 启动前按 INPUT-REQ-001 校验文本，按 INPUT-REQ-003 和 INPUT-REQ-005 校验相关设置。

### 数据示例

文本为 `abc`，目标输入框为空。按下开始组合键并保持时，目标内容为空；全部释放后按顺序发送 `a`、`b`、`c`，任务结束。

### 边界情况

| 条件 | 结果或建议结果 |
| --- | --- |
| 仍有一个启动组合键按住 | 保持等待，发送字符数为零 |
| 工具在后台，启动组合键全部释放 | 向当前键盘焦点发送文本 |
| 等待释放期间点击鼠标或按 Esc | 取消启动，发送字符数为零 |
| 等待释放期间按普通字符、方向键或无关功能键 | 保持等待，启动组合键释放后开始 |
| 系统报告 F22 持续按下，启动组合键及其他启动检查项均已释放 | 正常启动 |
| 开始快捷键注册失败 | 显示错误，允许修改快捷键，按钮启动可用 |
| 输入期间再次按开始快捷键并保持 | 当前任务中止，该次操作结束前保持中止状态 |

## INPUT-REQ-003 按钮倒计时启动

### 功能说明

使用者通过“开始输入”按钮启动倒计时，在等待期间选择目标输入位置。

### 处理规则

已确认：

1. 按钮名称为“开始输入”。设置页提供等待时间调整，默认值为 5 秒。
2. 输入页的按钮旁显示当前等待时间及选择输入位置的提示。
3. 点击后进入“倒计时”，按钮固定显示“取消输入”，点击取消本次任务。状态区显示“等待输入，剩余 N 秒，请选择输入位置。”。
4. 倒计时期间允许鼠标移动、点击及切换到目标程序。
5. 倒计时结束后，以当时的键盘焦点确定输入目标并发送文本。
6. 发送阶段执行 INPUT-REQ-004 的统一中止规则。
7. 倒计时期间禁用设置页签，保留输入页的剩余时间与取消按钮；任务结束后恢复页签操作。

参数与启动检查：

- 等待时间接受 1～60 秒的整数；无效值显示校验错误并阻止启动。
- 启动前按 INPUT-REQ-001 校验文本，按 INPUT-REQ-005 校验字符间隔。
- 本次倒计时采用启动时的等待时间，修改设置对下一次任务生效。
- 剩余秒数向上取整，例如剩余 4.2 秒显示 5 秒。
- 倒计时期间普通键盘操作继续倒计时，Esc 或开始快捷键取消任务。
- 倒计时结束时，工具自身仍在前台，或有 Ctrl、Alt、Shift、Win、鼠标按钮按住，均取消任务；工具在前台时提示选择目标位置。
- 普通字符、方向键及无关功能键的按下状态允许倒计时结束后启动。
- 倒计时提示保持目标程序的焦点，工具省去目标位置记录与自动焦点恢复。

### 数据示例

文本为 `abc`，等待时间为 5 秒，目标输入框为空：

| 时刻 | 操作与状态 | 目标内容 |
| --- | --- | --- |
| 0 秒 | 点击“开始输入”，按钮显示“取消输入”，状态显示“等待输入，剩余 5 秒，请选择输入位置。” | 空 |
| 2 秒 | 点击目标输入框并释放鼠标按钮，继续倒计时 | 空 |
| 5 秒 | 倒计时结束，开始发送 | 逐步出现 `abc` |
| 全部发送后 | 任务完成 | `abc` |

### 边界情况

| 条件 | 结果或建议结果 |
| --- | --- |
| 等待时间设置为 3 秒 | 下一次按钮启动使用 3 秒倒计时 |
| 倒计时期间点击目标输入框 | 继续倒计时 |
| 点击取消按钮、按 Esc 或开始快捷键 | 取消任务，发送字符数为零 |
| 等待时间为 0、1.5 或非数字 | 校验失败，阻止启动 |
| 倒计时结束时工具仍处于前台 | 取消并提示选择目标位置 |
| 倒计时结束时仍有修饰键或鼠标按钮按下 | 取消，发送字符数为零 |
| 倒计时结束时仅有普通字符或 F22 等无关功能键按下 | 正常开始发送 |
| 尝试切换到设置页 | 保持输入页，剩余时间及取消按钮可见 |

## INPUT-REQ-004 文本发送与人工中止

### 功能说明

两种启动方式共用顺序发送和人工中止规则。

### 处理规则

已确认的发送阶段事件规则：

| 事件 | 行为 |
| --- | --- |
| 鼠标移动 | 继续输入 |
| 鼠标按下 | 停止输入 |
| Esc 按下 | 停止输入 |
| 普通字符、方向键、修饰键及无关功能键 | 继续输入，目标程序处理原有按键效果 |
| 工具自身模拟的键盘事件 | 继续输入 |
| 全部文本发送完毕 | 结束任务 |

焦点行为采用已确认的简化方案：

- 事件发送到当时的键盘焦点位置，省去输入控件失焦检测。
- 鼠标按下或 Esc 执行中止。普通键盘操作继续任务，可能改变光标、内容或焦点，后续事件发送到当时的焦点。
- 其他程序主动取得焦点，且未发生鼠标按下或 Esc 中止事件时，继续输入，后续文本可能进入新位置。
- 工具省去对原目标窗口、输入控件和光标位置的恢复。

事件处理细则：

- 鼠标按下覆盖左键、右键、中键及侧键。键盘中止操作为 Esc，开始快捷键另按重复启动规则处理。
- 滚轮滚动继续输入，按下滚轮中键停止输入；仅松开按键或鼠标按钮保持任务状态。
- 工具根据注入标记与自身事件标识识别发送事件，自身事件继续任务。外部普通键盘事件继续任务，外部 Esc 事件执行中止规则。
- 检测到中止后取消尚未发送的内容，并中断字符间等待。
- 已交给系统的事件可能继续被处理，已输入内容保留。
- 中止操作保留原有效果，例如点击改变焦点、Esc 交由目标程序处理。普通人工输入可能与自动文本混合。工具内原本禁用按钮的保护规则见 INPUT-REQ-006。
- 中止后保持结束状态；新的独立启动从文本开头输入。首版省去暂停与续输功能。
- 同一时间仅有一个准备中或发送中的任务。重复启动按所处阶段取消或中止，快捷键及倒计时规则分别见 INPUT-REQ-002、INPUT-REQ-003。
- 输入发送失败时停止，并显示能够检测到的错误。

### 数据示例

输入文本为 `abcdef`。在目标收到 `abc` 且后续事件尚未发送时，使用者点击另一输入框：任务中止，第一个输入框保留 `abc`，剩余 `def` 取消。

如果部分后续事件已提交系统，其处理位置由焦点切换时机决定，已提交事件无法撤回。

再次独立触发开始时，完整待发送文本仍为 `abcdef`。

### 边界情况

| 条件 | 结果或建议结果 |
| --- | --- |
| 持续移动鼠标 | 连续发送文本 |
| 点击同一输入框中的其他位置 | 因鼠标按下而中止 |
| 点击另一个输入框 | 因鼠标按下而中止；已提交事件可能继续处理 |
| 按 Esc | 中止，保留已发送数量，目标程序处理 Esc 原有效果 |
| 按 Ctrl、方向键、退格键、普通字符键或无关功能键 | 继续任务，实际操作仍生效，内容可能与自动输入混合 |
| 工具发送自身的模拟事件 | 任务持续执行 |
| 外部程序自动取得焦点 | 按当前简化规则继续向新焦点发送 |
| 原输入框保留已发送内容后重新启动 | 从文本开头发送，可能与已有内容重复 |

## INPUT-REQ-005 输入速度与任务状态

### 功能说明

通过字符间隔设置控制发送速度，并展示任务准备、发送及结束状态。

### 处理规则

已确认：

- 按顺序逐个发送字符，字符之间使用固定间隔。
- 默认字符间隔为 50 毫秒，允许 10～1,000 毫秒的整数。
- 无效设置阻止启动并提示修正。更慢速度用于适应接收较慢的目标程序，实际接收能力需要验证。
- 发送成功表示事件已提交，目标完整接收需要另行检查。
- 状态模型采用[领域设计中的状态定义](design.md#状态变化与异常处理)，包含空闲、等待释放、倒计时、输入中、已完成、已中止和失败。
- 快捷键注册失败单独显示为该启动方式不可用，保留按钮启动能力。配置和空文本错误保持原任务状态。
- 状态通知保持目标程序的焦点。

已确认的界面反馈见 INPUT-REQ-006。

### 数据示例

文本 `abc`，字符间隔 50 毫秒，启动条件满足时发送 `a`，间隔后依次发送 `b`、`c`。全部事件提交后显示已完成，已发送字符数为 3；目标接收结果由兼容性验证确认。

### 边界情况

| 条件 | 建议结果 |
| --- | --- |
| 字符间隔为 10 或 1,000 毫秒 | 通过范围校验 |
| 字符间隔为 0、9、1,001、1.5 或空值 | 提示设置错误，阻止启动 |
| 目标程序处理速度低于发送速度 | 允许调慢间隔，实际接收效果需验证 |
| 部分发送后失败 | 停止发送，展示能够检测到的错误 |

## INPUT-REQ-006 界面操作与反馈

### 功能说明

通过输入页、设置页和关于页完成文本编辑、清理、清空、参数调整、任务状态查看及项目信息查阅。布局、配色和尺寸使用[界面视觉基准](design.md#界面视觉基准)，验收遵循[项目测试要求](../../project/principles.md#测试要求)。

### 处理规则

已确认：

- 输入页内容区域为多行编辑框。底部左侧为状态，右侧依次为字符数、清理、清空、开始输入；窄窗口采用状态在上、操作区在下并靠右的排列。
- 开始按钮在倒计时期间承担取消操作，文案与页签行为见 INPUT-REQ-003。等待快捷键释放和实际输入期间禁用开始按钮，输入时文案为“输入中…”。
- 空文本禁用清理和清空。初始化、操作提交、等待快捷键释放、倒计时、输入、安装准备及中止鼠标释放保护期间，清理和清空保持禁用。
- 输入期间实际鼠标按下仍按 INPUT-REQ-004 中止。点击原本禁用的操作按钮时，该次点击只中止任务并保留原文；按钮恢复后需再次独立操作。
- 清理按文本末尾向前逐行删除，`Ctrl+Z` 逐行撤销，`Ctrl+Y` 逐行重做。清空支持整体撤销和重做。后续编辑继续使用原生历史。
- 清理成功提示“已去除行尾空格，可按 Ctrl+Z 逐行撤销。”。没有匹配内容时提示“当前文本没有行尾空格。”，保留已有编辑历史。
- 清理过程中删除失败时停止后续操作，保留已完成的编辑，同步实际文本并显示“去除行尾空格未完成，请重试”。
- 字符数随清理、清空、撤销、重做及普通编辑更新。清空提示说明撤销方式。
- 清理和清空在悬停及键盘焦点时显示用途提示；可访问名称固定为按钮名称，详细描述说明操作范围及撤销方式。
- 设置项错误显示在对应参数下方，修正或恢复默认后消失。启动时有无效设置则定位到该项。
- 输入期间在现有说明位置显示已发送数量与总数，并提示“按 Esc 或点击鼠标停止”；结束后显示完成或中止结果。
- 设置页的中止说明为“输入期间，鼠标移动和普通按键继续；按 Esc 或点击鼠标停止。”
- 任务结束后按钮恢复为“开始输入”。
- Esc 中止后，文本编辑、清理、清空、页签切换、置顶及新的独立启动操作按各自规则执行。
- 标题栏图钉切换窗口置顶，提示文字为“置顶窗口”或“取消置顶”。置顶时显示蓝色背景及固定状态图标。目标程序仍可获得键盘焦点。
- 等待快捷键释放、倒计时和输入期间禁用图钉。输入中点击图钉遵循既有中止规则，该次点击保留置顶状态，随后独立点击才切换。
- 置顶状态读取或设置失败时显示可见错误，保留最后确认的状态并允许重试。
- 页签依次为“输入”“设置”“关于”，启动默认显示输入页。左右方向键循环切换可用页签，Home／End 选择首个／末个可用页签，隐藏面板退出键盘焦点顺序。
- 关于页显示应用名称、图标、应用元数据中的版本、Windows 64 位及用途说明。版本读取失败时显示错误并提供重试。
- 关于页提供项目主页、使用说明、问题反馈及 `hkhl888@foxmail.com` 联系邮箱。项目链接通过系统浏览器打开，邮箱通过默认邮件应用打开；打开失败时显示页内提示，原链接可再次点击。
- 关于页显示 `© 2026 sunnyx11`，MIT 许可证在面板内显示随应用打包的完整文本，支持离线查看及返回关于页。进入和返回时分别聚焦返回按钮和许可证按钮。
- 等待快捷键释放、倒计时、输入期间禁用关于页签；界面初始化、操作处理中及中止鼠标释放保护期间也保持禁用。从关于页启动任务时切回输入页展示状态，保持目标程序的键盘焦点。
- 输入中点击禁用的关于页签遵循同次点击只中止的规则；随后独立点击才进入关于页。

### 数据示例

原文为 `"a  \nb\t"`，清理后为 `"a\nb"`。第一次撤销得到 `"a  \nb"`，第二次撤销恢复原文；两次重做后得到 `"a\nb"`。

原文为 `abc`，点击清空后为空字符串；按 `Ctrl+Z` 恢复 `abc`，按 `Ctrl+Y` 再次清空。

输入过程中点击灰色的清理或清空按钮，任务中止而原文保留；再次独立点击才执行对应编辑。

按 Esc 中止任务后，点击清空，编辑框变为空字符串；填入新文本后可以启动下一次任务。

## INPUT-REQ-007 本地数据与运行生命周期

### 功能说明

约束文本及设置的保留方式、启动与退出行为和输入监听的数据使用。运行环境和兼容范围见[项目上下文](../../project/context.md#已知限制)。

### 处理规则

已确认：

- 软件启动时处于空闲状态。
- 窗口启动时处于普通层级，置顶仅在当前运行期间保留。最小化与还原保持置顶，退出后重新打开恢复普通层级。
- 发送过程保留系统剪贴板内容。
- 文本仅在本机处理，日志和错误提示省略待输入文本。
- 当前运行期间保留编辑框文本，关闭软件后清除；有效设置自动保存在当前用户应用配置目录，下次启动恢复。
- 退出软件时结束任务，释放快捷键与输入监听资源。
- 实际按键只用于必要的快捷键及中止判断，省去键入内容保存。
- 发送失败与快捷键注册失败的处理分别见 INPUT-REQ-004、INPUT-REQ-002。

### 数据示例

启动软件后准备文本 `abc`，剪贴板已有内容 `xyz`。发送任务完成后，原始文本仍为 `abc`，剪贴板仍为 `xyz`。关闭并重新启动软件后，编辑框为空，任务处于空闲状态。

### 边界情况

| 条件 | 建议结果 |
| --- | --- |
| 正在倒计时或发送时关闭软件 | 任务结束，快捷键及监听资源释放 |
| 比较发送前后的剪贴板内容 | 内容一致 |
| 查看错误提示或运行日志 | 保留诊断信息，省略待输入文本和实际键入内容 |
| 重新启动软件 | 编辑框为空，恢复上次保存的有效设置 |

## INPUT-REQ-008 应用更新

### 功能说明

从 GitHub 最新公开正式版本检查更新。安装版提供签名下载和确认安装，独立 EXE 提供手动下载入口。首次完整升级验证状态见[版本发布](../../release.md#验证状态)。

### 处理规则

- 默认在启动完成 10 秒后检查，其后每 24 小时检查。关于页提供手动检查和自动检查开关，偏好独立保存。
- 检查仅获取版本与说明。发现更新显示页签标记和页内状态，保持当前页签和系统焦点。
- 关于页展示目标版本、更新状态、下载进度、错误提示及当前阶段操作。具体发布说明由 GitHub Release 提供，关于页省略正文。
- 相同、较低版本及预发布版本保持当前安装；网络或清单错误显示提示并可重试。
- 安装版由使用者确认下载，完整下载并通过公钥签名验证后显示安装入口。检查、下载分别保持单操作，任务可同时运行。
- 独立 EXE 显示正式 Release 下载入口，由使用者退出后替换文件。安装记录与当前 EXE 位置共同确定安装模式，识别失败时采用手动替换。
- 安装入口提示重启清除全部编辑文本。每次安装请求需要独立确认，切换页签或任务启动会取消界面确认状态。
- 安装前保存最近有效设置。Rust 任务线程确认空闲后保留安装状态，阻止按钮及全局快捷键启动，释放钩子和快捷键后调用安装程序。
- 活动任务或中止释放保护期间延后安装，并保留当前进程内的已验证下载。安装启动失败时恢复原生资源，并显示重试信息。
- 安装程序接管后应用退出，成功安装后启动新版。编辑文本按 INPUT-REQ-007 清除，有效设置及更新偏好保留。
- 下载结果只保存在当前进程内存。签名验证失败时清除下载结果并禁止安装。更新请求和诊断省略编辑文本。
- 0.1.0 通过手动安装升级至带更新模块的版本，后续安装版使用上述更新流程。

### 数据示例

当前安装版为 `0.2.0`，清单包含正式版本 `0.3.0` 及发布说明正文。自动检查后显示“发现新版本 0.3.0”和“下载更新”，发布说明正文仅在 GitHub Release 中提供；点击“下载更新”获取并校验安装包。选择“安装并重启”后确认编辑文本清除提示，空闲时执行安装。重启后编辑框为空，等待时间、字符间隔、快捷键及自动检查偏好保持原值。

### 边界情况

| 条件 | 结果 |
| --- | --- |
| 检查或下载期间开始输入 | 输入任务继续由 Rust 处理 |
| 下载完成时任务仍活动 | 保留下载，任务结束后等待新的安装确认 |
| 确认安装与快捷键启动相邻发生 | 任务线程按先后顺序处理；已有任务阻止安装，已有安装状态阻止启动 |
| 下载断网或签名无效 | 显示错误，安装入口保持不可用，支持重新下载 |
| 取消安装确认 | 保留文本、设置和已下载更新 |
| 安装准备保存设置失败 | 保留文本和更新，显示错误，等待重试 |
| 安装启动失败 | 恢复钩子、快捷键和任务能力；恢复失败时显示具体错误 |
| 未配置构建公钥 | 显示配置提示，继续提供文本输入 |
