# Project 上下文

## 项目背景与用途

key-relay 面向 Windows 中允许键盘输入、但无法复制粘贴的场景。项目目标是将准备好的文本通过模拟键盘输入发送到目标程序，减少手工逐字输入。

## 系统目标

提供由使用者主动触发的文本输入工具。目标交互包含全局快捷键启动和按钮倒计时启动，详细规则、验收示例及待确认事项见[领域需求](../domains/text-input/requirements.md)。

## 主要能力

已识别的业务领域为[文本自动输入](../domains/text-input/overview.md)。首版目标功能包括文本准备、两种启动方式、顺序发送、人工中止、设置及状态展示。

## 当前系统状态

仓库包含许可证、项目代理说明、项目内 Skill、需求与设计文档，以及 [HTML 界面原型](../../prototypes/key-relay.html)。原型已支持页内交互验证，尚无 Tauri 桌面应用源码及运行入口。

Spec 根目录为 `docs/`，导航入口为 `docs/index.md`。首版需求与设计分别在对应主题文档中维护，正文区分已确认要求、待确认建议和实现验证状态。桌面输入能力尚未实现及验证。

## 技术环境与依赖

产品目标运行环境为 Windows。已确认的技术栈如下，具体依赖版本在项目初始化时确定。

| 技术 | 职责 |
| --- | --- |
| Tauri 2 | 桌面窗口、前后端通信及应用打包 |
| React + TypeScript | 文本编辑、设置、按钮、倒计时及任务状态展示 |
| Vite | 前端开发与构建 |
| Rust | 输入任务、倒计时、发送间隔、中止判断及资源释放 |
| Rust `windows` crate | 调用 Windows 原生输入与监听接口 |
| `tauri-plugin-global-shortcut` | 全局快捷键注册与事件处理 |
| WebView2 | Windows 上的界面运行环境 |

- 首版使用 React 自带状态管理，应用范围包含本地桌面界面和 Rust 原生逻辑。
- 最低系统版本、安装包格式、WebView2 安装策略及权限策略尚未确定。
- 仓库内 Spec 维护脚本通过 Node.js 执行；前端开发与构建也需要 Node.js。Rust 原生代码使用 Rust 工具链构建。
- 系统输入、任务调度及通信约束见[领域设计](../domains/text-input/design.md#技术决策与约束)。

## 已知限制

目标程序允许真实键盘输入，并不能证明其接受模拟输入。系统权限和目标程序的输入处理方式会影响实际接收结果，兼容范围需要实现后的验证依据。

首版运行环境的待确认建议：

- 支持 Windows 10、Windows 11 的 64 位桌面环境。
- 面向普通桌面程序和浏览器中的可编辑区域。
- 游戏、远程桌面、自定义控件及受保护输入区域逐项验证。

兼容性边界：

- 目标程序可以拒绝模拟输入；普通权限工具向高权限程序发送输入可能失败。
- Enter、Tab、输入法状态及目标控件逻辑会影响最终内容。
- “已完成”表示发送结束，使用者仍需检查目标内容。
- 安装包格式、WebView2 分发方式及权限策略尚未确定。
- 文本和设置的保留规则及其确认状态见 INPUT-REQ-007。
