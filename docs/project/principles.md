## 测试要求

功能验收以需求中的处理规则、数据示例和边界情况为依据。模拟输入的兼容性声明需要对应 Windows 环境和目标程序中的实际验证。

- 常规自动测试覆盖文本、设置、任务状态与界面；系统输入通过可控接收窗口进行集成验证。
- 会发送真实桌面事件的测试使用显式入口，常规测试保持当前桌面输入不变。
- RDP 实际兼容性由使用者后续人工验收，开发交付记录其待验证状态。
- 前端单元测试与源文件相邻，Rust 单元测试位于相应模块；浏览器测试位于 `tests/e2e/`，人工验收说明位于 `tests/manual/`。

界面验收对照[视觉基准](../domains/text-input/design.md#界面视觉基准)，覆盖以下场景：

- 默认桌面布局：检查页面结构、颜色、字体、控件尺寸与间距。
- 窄窗口：检查 390px、320px 视口，以及 520px、420px 视口断点两侧的布局；文字和控件完整显示。底部操作区另按工具窗口内容盒 560px 断点两侧检查，状态与按钮的位置符合视觉基准。
- 缩放：在 100% 和 150% 下检查可读性、控件完整性及页签等高。浏览器 CSS 缩放用于原型检查，桌面应用还需验证 Windows 系统缩放。
- 编辑框尺寸：分别使用基础高度 184px 和手动指定高度 320px，在相同视口及内容状态下切换页签，整体高度一致。实际编辑框高度同时满足共享面板填充规则；窄窗口的字符信息与底部操作区紧邻，拖动编辑框可以增大编辑区域。
- 动态状态：检查空闲、等待释放、倒计时、输入进度、完成、中止及错误提示。各状态的字体、字号、字重、行高、位置和布局与空闲提示一致，仅文本与整段文字颜色变化。倒计时按钮文案变化保持状态区与清空按钮的位置。
- 底部居中：横向布局下，单行和多行提示的整体垂直中心与按钮组一致，分别检查 100% 和 150% 缩放。窄窗口保持状态在上、按钮在下的排列。
- 键盘操作：焦点清晰可见，隐藏内容及禁用控件退出 Tab 焦点顺序。
- 字段错误：错误提示完整显示并允许增加内容高度；同一错误状态下切换页签仍保持等高。

## 文档维护要求

- Spec 根目录为 `docs/`，采用仓库内 [spec-coding Skill](../../.agents/skills/spec-coding/SKILL.md)。
- 首版需求建立期间，Project / Domain 按主题维护目标规范及当前事实，正文分别说明已确认要求、待确认建议和实现验证状态。
- 需求确认表示开发依据成立；已实现或已验证的声明需要对应证据。HTML 原型的验证范围与 Windows 桌面应用分别说明。
- 首版目标在 `requirements.md` 和 `design.md` 等主题文档中维护，待确认事项集中列于需求文档开头。
- 首版基准形成后的需求变化使用 Change：`proposed` 表示待确认，`accepted` 表示已确认且待完成，`completed` 表示实现验证和关联规范同步完成。
- Change 完成前，当前规范保留已生效规则，目标差异保存在该 Change 中。实现验证后同步关联规范，再标记为 `completed`。
- 本项目的首版约定优先于 Skill 中的通用生命周期规则，目录、模板、需求编号和索引检查仍按 Skill 执行。
- Change 保存需求差异；实施清单和验证输出保留在开发过程。
- 源文档更新后，依次运行索引生成和检查命令，两条命令均指定 `--specs-dir docs`。
- 三份索引由 Skill 脚本生成，维护入口见根目录 [AGENTS.md](../../AGENTS.md)。
